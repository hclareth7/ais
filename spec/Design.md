# Design — ais

## Soul — Ambient Intuition Design

ais is not a documentation browser.

ais is not an editor.

ais is not a dashboard.

ais is not a collection of panels.

ais is a reading surface.

A single floating sheet of knowledge suspended above the desktop.

The interface is not a tool.

The interface is an environment.

When a user opens ais, everything that normally competes for attention disappears:

- terminals
- browser tabs
- IDE sidebars
- toolbars
- status indicators

Only the document remains.

ais should feel like reading a beautifully typeset page floating above the operating system.

The interface exists only when it is needed and disappears the moment it stops helping the reader.

> The best interface is one that appears exactly when needed and disappears immediately after.

The experience is not that of an application.

The experience is that of a place.

A quiet place.

A familiar place.

A place where the mind can focus without interruption.

The emotional reference:

> Reading in ais should feel like reading in your favorite place in the world.

The emotional goals are:

- calm
- focus
- clarity
- immersion
- comprehension

ais should feel closer to holding a book than using software.

---

# Design Principles

## 1. The Content is the Protagonist

ais is not an application for managing documents.

ais is a place for understanding information.

Every visual decision must answer a single question:

> Does this improve reading?

If the answer is no, the element disappears.

If a feature makes reading harder, it does not ship.

---

## 2. Zero Presence

Every visual element must justify its existence.

If a component is not actively helping the user at that instant, it disappears.

By default:

- Menus hidden
- Panels hidden
- Tools hidden
- Controls hidden

Visible only:

- The content

The user should spend almost all of their time looking at the document.

Navigation, controls, tabs and settings are secondary.

---

## 3. Ambient Discovery

Interaction happens through proximity.

When the user approaches a relevant zone of the interface, the related tools emerge gently.

The controls do not wait to be found.

The controls come to the user.

Proximity triggers in v2:

- Approaching the left edge reveals navigation
- Approaching the right edge reveals document structure

The interface responds to the movement of attention.

Nothing remains visible without purpose.

---

## 4. Floating Knowledge

Documents should feel detached from the operating system.

ais is not a window.

ais is a floating reading surface.

---

## 5. Instant Navigation

Moving between documents should feel immediate.

No loading screens.

No transitions that slow the user down.

---

## 6. AI Native

ais is the ideal surface for consuming AI-generated content.

Markdown generated by humans and markdown generated by AI should be indistinguishable from a reading perspective.

---

## 7. Transparent Accessibility

Accessibility is not an add-on.

It is woven into every interaction so deeply that the user never notices it.

No extra icons.

No visual clutter.

No separate "accessible mode."

The default experience is the accessible experience.

---

## 8. Natural Input

ais responds to the way the body naturally moves.

A slight scroll.

A gentle hover.

A quick keystroke.

Every interaction should feel like an extension of the hand.

No gestures to memorize.

No hidden mechanics to discover.

---

## 9. Cognitive Calm

Human attention is a limited resource.

Every icon, border, color, animation or panel consumes part of that attention.

ais eliminates everything that does not contribute directly to comprehension.

The result is a visual experience that is serene and free of noise.

---

## Interface Behavior

The interface must behave like an intelligent and discreet presence.

Never aggressive.

Never dominant.

Never the protagonist.

The ideal feeling:

> The software seems to know what I need before I have to look for it.

Not because it guesses.

But because it understands context through proximity, position, and the natural flow of reading.

---

## Expected Outcome

When these principles are implemented correctly:

- The user spends less time navigating
- The user spends less time looking for tools
- The user spends more time understanding information
- Cognitive load decreases
- Reading speed increases
- Knowledge retention improves

The interface disappears.

Comprehension remains.

# Input Philosophy

## Desktop First

ais is designed for the desktop environment.

The primary input devices are:

- Built-in trackpad (laptop)
- External mouse
- Keyboard

Every interaction must work flawlessly with all three.

Future adaptations for web, mobile, and touch interfaces will follow.

The desktop experience is the reference implementation.

---

## Trackpad Interactions

Scroll:

```text
Two-finger vertical scroll → Document scroll
Two-finger horizontal scroll → No action (prevents accidental navigation)
```

Hover zones:

```text
Cursor rests near left edge (within 24px) → Navigation reveals
Cursor rests near right edge (within 24px) → TOC reveals
```

The 24px activation zone ensures that trackpad users with lower precision can still trigger hover navigation reliably.

Pinch:

```text
Pinch to zoom → Document zoom (if OS supports gesture forwarding)
```

---

## External Mouse Interactions

Scroll:

```text
Scroll wheel → Document scroll
Ctrl + Scroll wheel → Document zoom
Shift + Scroll wheel → Horizontal scroll (for wide code blocks only)
```

Hover zones:

```text
Same as trackpad (24px edge zones)
```

Side buttons (if available):

```text
Back button → Previous document in history
Forward button → Next document in history
```

---

## Keyboard Navigation

ais is fully operable without a mouse.

Core navigation:

```text
Ctrl + K         → Command Palette
Ctrl + B         → Toggle navigation panel
Ctrl + Shift + O → Toggle Table of Contents
Tab / Shift+Tab  → Move between interactive elements
Enter             → Activate focused element
Escape            → Close any open panel
```

Document navigation:

```text
Arrow Up / Down   → Scroll document
Home              → Jump to document start
End               → Jump to document end
Page Up / Down    → Scroll by viewport
```

The keyboard is not a fallback.

It is a first-class input method.

---

## Interaction Minimalism

The best interaction is one the user does not think about.

Rules:

- If the user must remember a gesture, simplify it
- If the user must look away from the document to find a control, redesign it
- If the user must perform more than one action to accomplish a common task, reduce it

ais should feel like the document responds to intention, not to commands.

The application window has no OS-provided decorations (title bar, borders, close/minimize/maximize buttons). The reader surface IS the window boundary.

Visual characteristics:

- frameless — no OS window chrome
- semi-transparent
- soft edges (rounded corners define the window shape)
- subtle depth
- calm appearance
- no hard boundaries

# ais as an AI Surface

ais is the ideal destination for AI-generated Markdown.

The reading experience for streamed content must match the quality of a static document.

---

## Progressive Rendering

Content renders paragraph by paragraph.

Each paragraph appears complete.

No character-by-character typing effect.

Behavior:

```text
Token buffer accumulates
    ↓
Complete paragraph detected
    ↓
Paragraph renders with subtle fade-in
    ↓
Scroll position preserved
```

Fade-in duration:

```text
80ms
```

The viewport never jumps.

If the user is reading above the insertion point, new content appears below without disturbing scroll position.

If the user is following the stream at the bottom, the viewport advances smoothly.

---

## Streaming Status

Visual indicator:

```text
Streaming    → Subtle pulse on document border (1px accent glow)
Complete     → Border returns to default
Error        → Border flashes once, status appears in Command Palette
```

No spinners.

No progress bars.

No loading text.

The indicator is peripheral.

The reader never needs to look away from the content.

---

## Automatic TOC Generation

The Table of Contents builds as headings arrive.

Behavior:

```text
New heading rendered
    ↓
TOC entry added
    ↓
TOC updates without animation
```

If the TOC panel is open during streaming, new entries appear in place.

If the TOC panel is closed, entries accumulate silently.

---

## Code Block Rendering

Language detection:

```text
Fenced block opens → detect language from info string
No info string     → auto-detect from content
Fallback           → plain text
```

Syntax highlighting applies after the block closes.

During streaming, code blocks render as monospace plain text.

After the closing fence arrives, highlighting applies in one pass.

No incremental re-highlighting.

---

## Collapsible Sections

Sections collapse at heading boundaries.

```text
Click heading    → Toggle section collapsed/expanded
Alt + Click      → Collapse all sections at same level
```

Default state during streaming:

```text
All sections expanded
```

Default state for completed documents:

```text
All sections expanded
```

User collapse state persists per document.

---

## Large Document Handling

Maximum rendered document size:

```text
No artificial limit
```

Performance strategy:

```text
Virtualized rendering for documents exceeding 5000 lines
Only visible paragraphs and a 500-line buffer render to DOM
```

The user must never perceive a performance boundary.

# AI Streaming Experience

## Live Rendering

Markdown parses incrementally.

Each render pass produces stable output.

No flicker.

No layout shift.

Render strategy:

```text
Buffer tokens until block boundary
    ↓
Parse buffered markdown
    ↓
Diff against current DOM
    ↓
Apply minimal DOM mutations
```

Block boundaries:

```text
- Double newline (paragraph break)
- Closing fence (code block)
- List item completion
- Heading completion
- Table row completion
```

Text that has already rendered never re-flows.

## Streaming Tab

A streaming tab is a tab that is receiving content.

It looks like a regular tab.

Almost.

The difference is a single visual signal: a 1px bottom border that breathes.

Streaming tab properties:

```css
/* Base tab (inherits all .tab styles) */
position: relative;

/* Streaming indicator — animated bottom border */
.tab.streaming::after {
  content: '';
  position: absolute;
  bottom: 0;
  left: 20%;
  right: 20%;
  height: 1px;
  background: var(--stream-glow);
  border-radius: 1px;
  animation: stream-pulse 2s ease-in-out infinite;
}
```

The pulse animation:

```css
@keyframes stream-pulse {
  0%, 100% { opacity: 0.15; }
  50% { opacity: 0.55; }
}
```

| Property | Value |
|----------|-------|
| Indicator width | 60% of tab width (centered) |
| Indicator height | 1px |
| Indicator color | var(--stream-glow) |
| Pulse duration | 2s |
| Pulse easing | ease-in-out |
| Pulse opacity range | 0.15 — 0.55 |
| Pulse iteration | infinite (while streaming) |

When streaming completes:

```text
Animation stops
    ↓
Indicator fades out (200ms)
    ↓
Tab becomes a regular tab
    ↓
No visual difference from a file tab
```

The streaming tab label:

```text
Format: "AI: {first 30 characters of prompt}..."
Example: "AI: How do I configure RBAC..."
```

If the prompt is shorter than 30 characters, no ellipsis.

The tab title attribute shows the full prompt for tooltip on hover.

When reduced motion is preferred:

```text
No animation
Indicator is static at opacity 0.35
Indicator disappears instantly on completion
```

## Auto-Scroll Behavior

The viewer follows new content as it arrives.

But only if the reader is already at the bottom.

Rules:

```text
User is at the bottom of the document
    ↓
New content arrives
    ↓
Viewport scrolls to keep the latest content visible
    ↓
Scroll is smooth (60ms ease-out)
```

```text
User scrolls up manually
    ↓
Auto-scroll pauses
    ↓
"Resume" pill appears at the bottom of the viewer
    ↓
New content continues to arrive below, silently
```

```text
User clicks "Resume" pill
    OR
User scrolls back to the bottom
    ↓
Auto-scroll resumes
    ↓
"Resume" pill disappears
```

The "Resume" pill:

```css
position: fixed;
bottom: 80px;
left: 50%;
transform: translateX(-50%);
padding: 6px 16px;
font-size: 12px;
color: var(--text-secondary);
background: var(--surface-elevated);
backdrop-filter: blur(20px);
-webkit-backdrop-filter: blur(20px);
border: 1px solid var(--border);
border-radius: 20px;
cursor: pointer;
z-index: 28;
opacity: 0;
transition: opacity 0.15s;
```

The pill appears with a 150ms fade-in.

The pill disappears with a 120ms fade-out.

Content of the pill:

```text
↓ Resume following
```

No icon.

Just text and a subtle arrow.

The pill follows the glass surface aesthetic.

It does not compete with the ControlStrip.

## Streaming Caret

A thin blinking cursor marks the end of the stream.

The caret tells the reader: content is still arriving.

```css
.stream-caret {
  display: inline-block;
  width: var(--stream-caret-width);
  height: var(--stream-caret-height);
  background: var(--stream-caret);
  border-radius: 1px;
  animation: caret-blink 1s step-end infinite;
  vertical-align: text-bottom;
  margin-left: 2px;
}

@keyframes caret-blink {
  0%, 100% { opacity: 1; }
  50% { opacity: 0; }
}
```

| Property | Value |
|----------|-------|
| Width | 2px |
| Height | 1.2em (matches line height) |
| Color | var(--stream-caret) |
| Blink rate | 1s (500ms on, 500ms off) |
| Blink style | step-end (sharp on/off, not fade) |

The caret appears at the end of the last rendered text.

When a new paragraph renders, the caret moves to the end of the new paragraph.

When streaming completes, the caret fades out (200ms) and is removed from the DOM.

When reduced motion is preferred:

```text
No blink animation
Caret is static at opacity 0.6
Caret still fades out on completion
```

```text
If Command Palette is open       → Close palette (existing behavior)
Else if streaming is active      → Stop streaming
Else if navigation is open       → Close navigation (existing behavior)
```

The priority chain preserves existing escape behavior.

When streaming is stopped by the user:

```text

    ↓
Tab pulse animation stops
    ↓
Tab indicator fades out (200ms)
    ↓
Stop button fades out (120ms)
    ↓
Content remains as-is (no deletion)
    ↓
A subtle status line appears below the last content:
    "Stopped"
```

The "Stopped" status line:

```css

color: var(--text-ghost);
margin-top: 24px;
padding-top: 12px;
border-top: 1px solid var(--border);
```

## Contrast Integrity

WCAG AA is the baseline.

The application enforces contrast automatically.

```text
User adjusts transparency or background
    ↓
Engine calculates text contrast ratio against effective background
    ↓

```

The user is never blocked.

The application advises.

The warning is non-intrusive:

```text

Tooltip: "Low contrast — readability may be reduced"
```

# Technical Constraints

Design aspirations must survive contact with platform reality.

---

## System Wallpaper Blur

Ideal behavior:

```text
Capture system wallpaper → Apply Gaussian blur → Use as window background
```

Platform support:

```text
macOS       Supported via NSVisualEffectView
Windows     Supported via DWM (Desktop Window Manager) blur APIs
Linux X11   Supported via compositor (picom, compiz)
Linux Wayland   Limited — compositor-dependent, no standard protocol
```

Fallback chain:

```text
System wallpaper blur available?
    ├─ Yes → Use system wallpaper blur
    └─ No  → Fall back to Frost mode (solid color + blur texture)
```

The fallback must be visually coherent.

The user should not feel punished for their platform.

---

## Contrast Safety

Transparency and custom backgrounds create contrast risk.

The application must validate text readability in real time.

```text
On every transparency or background change:
    ↓
Sample effective background color at text regions
    ↓
Calculate contrast ratio (WCAG 2.1 algorithm)
    ↓
Ratio ≥ 4.5:1  → No action
Ratio < 4.5:1  → Show subtle warning
Ratio < 3.0:1  → Auto-suggest minimum opacity adjustment
```

The validation runs on:

```text
- Transparency change
- Background mode change
- Theme change
- Custom image selection
```

---

## GPU and Performance

Glass effects require GPU acceleration.

```text
backdrop-filter: blur()    → GPU compositing required
Multiple layered surfaces  → GPU memory consumption
Animation at 60fps         → GPU render pipeline
```

Detection:

```text
Application start
    ↓
Probe GPU capabilities
    ↓
Full support    → Enable all glass effects
Partial support → Reduce blur radius, disable layered blur
No GPU          → Solid backgrounds, no blur, no transparency
```

Performance tiers:

```text
Tier 1 (Full)
  - All blur effects
  - All transparency levels
  - Layered glass surfaces

Tier 2 (Reduced)
  - Blur radius capped at 15px
  - Transparency minimum 80%
  - Single-layer blur only

Tier 3 (Minimal)
  - Solid backgrounds only
  - No backdrop-filter
  - Full opacity
  - All functional features remain
```

The reading experience must be excellent at every tier.

Visual richness degrades gracefully.

Functionality never degrades.
